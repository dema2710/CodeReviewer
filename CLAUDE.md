# CLAUDE.md

Контекст для відновлення роботи над проєктом. **README.md — документація для користувачів**
(запуск, API, ліміти, troubleshooting). Тут — те, чого там немає: домовленості, підводні камені, стан.

Якщо ти читаєш це на початку сеансу: спочатку цей файл, потім `README.md`, потім `server.js`.

## Що це

Веб-додаток «AI Code Reviewer»: користувач вставляє код або GitHub-посилання → DeepSeek
повертає структурований звіт (критичні баги / оптимізація / стиль + оцінка 0–100 + вердикт).

Стек: Node.js 18+ (ESM), Express 4, `openai` SDK (сумісний з DeepSeek API), axios, Tailwind CDN.

## Архітектура (навмисно проста)

| Файл | Роль | Розмір |
|---|---|---|
| `server.js` | **весь** бекенд: роути, GitHub-парсер, клієнт DeepSeek, нормалізація відповіді | ~30 КБ |
| `public/index.html` | **весь** фронтенд: Tailwind CDN + vanilla JS, без збірки | ~33 КБ |

Це свідомий вибір — **два файли, без фреймворків і без build-кроку**. Не розносити на модулі
й не додавати бандлер без явного прохання.

Потік запиту `/api/analyze`:
`createRateLimiter()` → валідація body → якщо `githubUrl`: `parseGitHubUrl` → `fetchGitHubFile`
або `fetchGitHubRepo` → `analyzeWithDeepSeek` → `extractJson` → `normalizeAnalysis` → JSON на фронт.

Ключові функції в `server.js`: `buildUserPrompt` (94), `parseGitHubUrl` (131), `fetchGitHubFile` (218),
`scoreFile`/`isAnalyzable` (283/310, евристика вибору файлів з репо), `fetchGitHubRepo` (346),
`extractJson` (414), `normalizeAnalysis` (470), `analyzeWithDeepSeek` (482), `createRateLimiter` (522).

Роути: `GET /api/health` (553), `POST /api/analyze` (563), 404 для `/api/*` (615), error handler (619).

Константи (рядки 31–35): `MAX_CODE_CHARS` 60 000, `MAX_REPO_FILES` 6, `MAX_FILE_BYTES` 150 000,
`GITHUB_TIMEOUT_MS` 15 с, `AI_TIMEOUT_MS` 180 с.

## Домовленості

- **Мова:** усі тексти для користувача — інтерфейс, повідомлення про помилки з `httpError`,
  вердикти — **українською**. Коментарі в коді теж українською. Код і назви — англійською.
- **ESM** (`"type": "module"`), імпорти на початку файлу, без `require`.
- **Перевірка — вручну:** `npm start` і реальний сценарій у браузері.
- **Модель ніколи не повертає сирий JSON напряму на фронт** — тільки через `normalizeAnalysis`.
  Якщо додаєш поле у промпт, додай його і в `normalizeSection`/`normalizeAnalysis`, інакше
  воно загубиться.
- Помилки з `expected: true` у `httpError` — це очікувані помилки користувача (не 500),
  вони логуються інакше. Дотримуватись цієї конвенції.

## Підводні камені

- **Rate limit 20 запитів / 10 хв на IP.** При ручному тестуванні легко впертись у 429
  і вирішити, що щось зламалось. Обходити — перезапуском сервера (лічильник у пам'яті)
  або тимчасовим підняттям `max` у `createRateLimiter`.
- **`.env` обов'язковий** для `/api/analyze`; без ключа сервер стартує, але роут віддає помилку.
  Стан видно на `/api/health` (`apiKeyConfigured`, `githubTokenConfigured`).
- Ключі до DeepSeek/GitHub — **тільки в `.env`**, він у `.gitignore`. Не писати їх у код
  і не виводити в логи.
- `extractJson` терпить markdown-обгортки та сторонній текст навколо JSON, бо модель
  не завжди слухається. Не «спрощувати» це до простого `JSON.parse`.
- Ліміт GitHub API без токена — 60 запитів/год, і репозиторій з багатьма файлами
  з'їдає кілька запитів одразу.

## Як перевірити, що все працює

```bash
npm start                                   # або npm run dev (Node 18+, --watch)
curl http://localhost:3000/api/health       # має бути "status":"ok"
```

Далі — http://localhost:3000, вставити фрагмент коду й подивитись, чи рендеряться три картки.

## Стан проєкту

Проєкт **готовий і працює**. Незавершених задач, заглушок і `TODO` у коді немає.

Реалізовано повністю:

- аналіз вставленого коду з вибором мови;
- аналіз окремого GitHub-файлу, гілки або цілого репозиторію (до 6 файлів);
- три категорії звіту, оцінка 0–100, вердикт, копіювання звіту в Markdown;
- нормалізація відповіді моделі, обробка помилок, rate limit, health-check;
- фронтенд повністю в `public/index.html`, без збірки;
- `README.md` — документація для користувача, `CLAUDE.md` — цей файл.

Якщо після змін у коді щось із цього перестало бути правдою — оновити цей розділ.
